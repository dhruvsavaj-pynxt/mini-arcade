# Mini Arcade

A small collection of free browser games. No download, no account, no build tools needed to play. Scores are saved on the device with `localStorage`.

**Games:** Snake, Quick Tap (reaction test), Tic-Tac-Toe, Memory, Breakout, 2048, Whack-a-Mole.

## Project layout

```
index.html, games/, sitemap.xml, robots.txt   generated by scripts/build.js (not committed)
scripts/build.js        builds the static site (hub, game pages, sitemap, robots)
scripts/games.js        single list of games: titles, SEO text, how to play, accent color
scripts/check-links.js  validates generated pages (links, metadata, JSON-LD)
js/store.js             localStorage helpers and shared utilities
js/main.js              mounts the game for the current page
js/<game>.js            one file per game
styles.css              shared styles
deploy/                 nginx config, load balancer, docker-compose
Dockerfile              container image (build + nginx)
.github/workflows/      CI and deployment pipelines
```

## Run locally

Requires Node.js 18 or newer.

```powershell
npm run build
```

Then open `index.html` in a browser. The generated pages use relative paths, so opening the files directly works. To test with a local server instead:

```powershell
npx --yes serve .
```

To get real canonical URLs and sitemap entries, set your public address first:

```powershell
$env:SITE_URL = "https://your-domain.com"; npm run build
```

## Scripts

| Command | What it does |
| --- | --- |
| `npm run build` | Generates `index.html`, `games/*.html`, `sitemap.xml`, `robots.txt` |
| `npm run check` | Validates the generated site |
| `npm run check:strict` | Same, and fails if the placeholder domain is still present |

## Add a game

1. Create `js/<name>.js` that registers itself with `Arcade.games.push({ id, title, tag, blurb, accent, bestLabel, mount })`. `mount(root)` renders into `root` and may return a cleanup function. Use `Arcade.store.getBest` and `Arcade.store.saveBest` for best scores.
2. Add an entry to `scripts/games.js` with `id`, `file` (the script name without `.js`), `title`, `tag`, `accent`, `blurb`, `seoTitle`, `seoDescription`, and `howTo`.
3. Run `npm run build` and `npm run check`.

The hub page, game page, sitemap, and "More games" links update automatically.

## Ads

Ad containers are already placed on the hub and game pages (`<aside class="ad-slot" data-ad-slot="…">`). They stay hidden while empty, so there is no gap and no layout shift when an ad fills one. When you add an ad network:

- Insert the ad code into the slots in `scripts/build.js`.
- Allow the ad domains in the Content Security Policy in `deploy/nginx.conf` (script, image, and frame sources).

## Deployment

Three GitHub Actions workflows live in `.github/workflows/`:

| Workflow | Trigger | What it does |
| --- | --- | --- |
| `ci.yml` | Pull requests, pushes to `main` | Builds, validates, and smoke-tests the Docker image |
| `deploy-pages.yml` | Pushes to `main` | Deploys the static site to GitHub Pages |
| `deploy-container.yml` | Pushes to `main` | Builds the container image and pushes it to GitHub Container Registry |

Before the deploy workflows will run:

1. Add a repository variable `SITE_URL` with your public address (for example `https://your-domain.com`).
2. For GitHub Pages: Settings → Pages → Source → "GitHub Actions".

### Load-balanced container hosting

`deploy/docker-compose.yml` runs two app containers behind an nginx load balancer (`deploy/lb.conf`). The load balancer uses least-connections and retries the other container when one fails. HTTPS is not terminated here; put it in front with your cloud load balancer or CDN.

```powershell
cd deploy
$env:SITE_URL = "https://your-domain.com"; docker compose up -d --build
```

Open http://localhost. Each container exposes `/healthz` for health checks.

## Notes

- Best scores are stored only in the browser. They are never uploaded.
- The generated HTML files are ignored by git. CI and the Dockerfile rebuild them from source.
